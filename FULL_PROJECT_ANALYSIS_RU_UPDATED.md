# Полный анализ проекта PiggyVault (Июль 2026)

## 1. Обзор архитектуры
Проект представляет собой мобильное приложение для накопления средств, построенное на Flutter.
*   **Управление состоянием:** Riverpod (активно используется для провайдеров данных и логики).
*   **База данных:** Drift (SQLite) для реляционных данных (цели, депозиты, профиль).
*   **Локальное хранилище:** Hive для настроек и простого состояния (onboarding, API ключи).
*   **Навигация:** GoRouter.
*   **UI-система:** Собственная система компонентов (SurfaceCard, AppButton), ориентированная на неоновый/киберпанк стиль.

## 2. Инвентаризация технического долга

### 2.1 Хардкод N-целей (Критично)
*   **Проблема:** Таблица `Deposits` в `database.dart` содержит жестко заданные колонки `goalAAmount` и `goalBAmount`. Логика распределения в `SavingsNotifier` также завязана на две цели.
*   **Последствия:** Невозможно добавить третью цель без изменения схемы БД и переписывания значительной части бизнес-логики.
*   **Решение:** Переход к таблице `DepositAllocations(deposit_id, goal_id, amount)`.

### 2.2 Дублирование кода в Onboarding
*   **Проблема:** Экраны `goal_a_setup_screen.dart` и `goal_b_setup_screen.dart` идентичны на ~90%.
*   **Решение:** Создание универсального `GoalSetupScreen(goalIndex: ...)` или использование параметров маршрута.

### 2.3 God Object: SavingsNotifier
*   **Проблема:** `SavingsNotifier` выполняет слишком много функций:
    *   Сохранение депозитов.
    *   Расчет XP и уровней.
    *   Управление стриами (через `StreakService`).
    *   Проверка достижений.
    *   Логика лутбоксов.
    *   Обновление отрядов (Squads).
*   **Решение:** Декомпозиция на доменные сервисы (`XpDomainService`, `AchievementDomainService`, `DepositDomainService`).

### 2.4 Хрупкий парсинг AI
*   **Проблема:** В `BountyProvider` и `OpenRouterService` используется строковая манипуляция для извлечения JSON из ответов ШИ.
*   **Решение:** Использование JsonSchema или более надежных библиотек для валидации ответов.

### 2.5 Локализация
*   **Проблема:** Огромная карта в `l10n.dart` затрудняет поддержку и масштабирование.
*   **Решение:** Переход на стандартные `.arb` файлы.

## 3. Анализ базы данных (v8)
Текущая версия схемы — 8.
*   Отсутствуют поля `updated_at` и `is_synced` во многих таблицах, что блокирует внедрение облачной синхронизации.
*   `UserProfiles` использует фиксированный ID (1), что ограничивает поддержку нескольких профилей или синхронизацию между устройствами.

## 4. Состояние UI-компонентов
*   `DualProgressRing` и `SplitSlider` жестко завязаны на две цели (A и B). Требуется рефакторинг для поддержки списка целей.
