# Глубокий анализ проекта PiggyVault (Июль 2026)

## 1. Архитектурный обзор

Проект представляет собой кроссплатформенное приложение на Flutter, построенное с использованием современных подходов к управлению состоянием и хранению данных.

### Стек технологий:
*   **Управление состоянием:** `Riverpod` (StateNotifier, Provider). Это обеспечивает высокую тестируемость и модульность.
*   **База данных:** `Drift (SQLite)`. Используется для сложных реляционных данных (цели, депозиты, профили пользователей). Текущая версия схемы: 8.
*   **Локальное хранилище:** `Hive`. Используется для простых настроек (SettingsService) и в-апп уведомлений.
*   **Навигация:** `GoRouter`. Декларативный роутинг с поддержкой ShellRoute для нижней навигации.
*   **Интеграция с ИИ:** `OpenRouter` (DeepSeek). Используется для генерации финансовых советов и ежедневных заданий (Bounties).
*   **Удаленное управление:** Собственный Node.js сервер в `remote_server/` для стриминга экрана и управления ПК.

## 2. Обнаруженные критические проблемы

### 2.1 Ограничение "N-Goals" (Hardcoded Goals)
**Статус:** Критично 🚨
Текущая архитектура жестко ограничена двумя целями (`goal_a` и `goal_b`). Это прослеживается в:
*   `lib/data/database.dart`: Таблица `Deposits` имеет колонки `goalAAmount` и `goalBAmount`.
*   `lib/core/providers/savings_notifier.dart`: Метод `createDeposit` рассчитывает распределение только между двумя целями.
*   `lib/data/backup_service.dart`: Экспорт в CSV/JSON завязан на статичные ID целей.
*   `lib/features/onboarding/`: Отдельные экраны для настройки цели А и цели Б.

### 2.2 God Object: SavingsNotifier
**Статус:** Высокий приоритет ⚠️
Метод `SavingsNotifier.createDeposit` (около 250 строк кода) нарушает принцип единственной ответственности. Он одновременно:
1. Выполняет транзакцию в БД.
2. Рассчитывает XP и уровни.
3. Обрабатывает логику стриков (StreakService).
4. Проверяет достижение ачивок (AchievementService).
5. Генерирует лутбоксы.
6. Обновляет состояние сквадов.
7. Проверяет баунти и квесты.

### 2.3 Дублирование кода в Onboarding
**Статус:** Средний приоритет ⚠️
Файлы `goal_a_setup_screen.dart` и `goal_b_setup_screen.dart` практически идентичны. Это усложняет поддержку и внесение изменений в дизайн.

### 2.4 Хрупкость парсинга ИИ-ответов
**Статус:** Низкий/Средний приоритет ⚠️
`BountyNotifier` полагается на текстовую замену "```json" и `json.decode`. При нестабильном ответе от модели это может приводить к ошибкам.

## 3. Технический долг

*   **Фрагментация данных:** Данные разбросаны между Drift и 5-ю разными боксами Hive (`milestones_box`, `notifications_box` и др.). Это создает риски нарушения консистентности при сбоях (одна база обновилась, другая — нет).
*   **Backup Service:** Ручная сериализация каждой таблицы в `BackupService` требует ручного обновления при любом изменении схемы БД.
*   **Локализация:** Используется кастомный `AppLocalizations` с жестко прописанной Map, вместо стандартных ARB-файлов. Это может затруднить работу профессиональных переводчиков.

## 4. Оценка безопасности и инфраструктуры

*   **Remote Server:** Использует SHA-256 challenge-response для аутентификации, что хорошо. Однако пароль по умолчанию прописан в коде.
*   **Cloud Sync:** Приложение сейчас полностью "Offline First". Для перехода к Фазе 2 (Squads, Cloud Sync) потребуется внедрение UUID (частично реализовано) и полей `updated_at` для разрешения конфликтов.

## 5. Рекомендации по дальнейшей разработке (Phase 2)

1.  **Рефакторинг N-Goals:**
    *   Миграция БД: создание таблицы `DepositAllocations`.
    *   Унификация экранов настройки целей в один переиспользуемый виджет/экран.
2.  **Декомпозиция SavingsNotifier:**
    *   Выделение логики расчета геймификации в чистые `Domain Services`, которые возвращают результат расчета, не выполняя запись в БД самостоятельно (или выполнение через специализированные Command-классы).
3.  **Интеграция Firebase/Supabase:**
    *   Перенос `Squads` и `JointGoals` из локальных таблиц в реальное облачное хранилище.
    *   Реализация `SyncService` для фоновой синхронизации локальных данных.
4.  **Улучшение UI/UX:**
    *   Консолидация систем наград (Achievements и Badges) в единую сущность `Reward`.
