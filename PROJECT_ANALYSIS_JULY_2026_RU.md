# Полный технический анализ проекта PiggyVault (Июль 2026)

## 1. Обзор архитектуры
Проект представляет собой мобильное приложение на Flutter, использующее современные подходы к разработке:
*   **Управление состоянием:** Riverpod (в связке с StateNotifier).
*   **База данных:** Drift (SQLite) для реляционных данных и Hive для простых настроек/локального стейта.
*   **Навигация:** GoRouter (декларативный подход).
*   **AI-интеграция:** OpenRouter (модели DeepSeek/другие) для генерации квестов и анализа цен.
*   **Стиль:** Чистый UI с элементами киберпанка/неона.

## 2. Инвентаризация технического долга

### 2.1 Проблема N-Goals (Критично) 🚨
Текущая архитектура жестко ограничена двумя целями (`goal_a` и `goal_b`). Это пронизывает все слои приложения:
*   **БД (`database.dart`):** Таблица `Deposits` содержит колонки `goalAAmount` и `goalBAmount`.
*   **Логика (`SavingsNotifier.dart`):** Метод `createDeposit` принимает `goalAPercent` и распределяет средства только между двумя идентификаторами.
*   **UI (`DualProgressRing.dart`, `SplitSlider.dart`):** Виджеты рассчитаны строго на два значения.
*   **Геймификация (`AchievementService.dart`):** Проверки достижений (например, `halfway_ps5`) завязаны на ID `goal_a`.

### 2.2 God Object: SavingsNotifier ⚠️
Класс `SavingsNotifier` в `lib/core/providers/savings_notifier.dart` выполняет слишком много задач:
*   Управление транзакциями БД.
*   Расчет опыта (XP) и уровней.
*   Логика стриков (серий).
*   Валидация достижений.
*   Обновление отрядов (squads).
*   Обработка критических ударов (critical hits).
Это затрудняет тестирование и расширение функционала.

### 2.3 Дублирование кода в Onboarding ⚠️
Экраны `GoalASetupScreen` и `GoalBSetupScreen` идентичны примерно на 90%. Это классический пример технического долга "Copy-Paste", который усложнит поддержку при изменении дизайна или логики настройки целей.

### 2.4 Хрупкий парсинг AI-ответов ⚠️
Интеграция с OpenRouter (`BountyProvider.dart`) полагается на строковые манипуляции (`replaceAll('```json', '')`) и `json.decode`. При некорректном ответе модели (например, если она добавит пояснительный текст) приложение может упасть или использовать fallback-данные.

### 2.5 Локализация ⚠️
Вместо стандартных ARB-файлов используется огромная статическая карта в `lib/core/providers/l10n.dart`. Это затрудняет работу профессиональных переводчиков и увеличивает размер основного кода.

### 2.6 Готовность к Cloud Sync ⚠️
Для реализации облачной синхронизации (Фаза 2) текущая база данных имеет недостатки:
*   Отсутствие поля `updatedAt` во многих таблицах.
*   Отсутствие флага `isSynced`.
*   Использование автоинкрементного ID `1` для профиля пользователя.

### 2.7 Качество кода (Linter) ⚠️
Анализ проекта (`flutter analyze`) выявил 11 замечаний:
*   **Использование BuildContext после асинхронных вызовов:** В файлах `dashboard_screen.dart` и `settings_screen.dart`.
*   **Неиспользуемые переменные:** В `goal_detail_screen.dart`, `price_analysis_screen.dart`, `daily_bonus_provider.dart`, `daily_bonus_dialog.dart`, `settings_screen.dart`.
*   **Неиспользуемые методы:** В `pets_screen.dart` (`_calculatePetLevel`, `_xpForNextLevel`, `_xpProgressInLevel`).

## 3. Рекомендации по развитию (Phase 2)

### 3.1 Рефакторинг базы данных
1.  Создать таблицу `DepositAllocations(depositId, goalId, amount)`.
2.  Мигрировать данные из старых колонок `goalAAmount/goalBAmount`.
3.  Добавить `updatedAt` и `isSynced` для всех сущностей.

### 3.2 Декомпозиция SavingsNotifier
Вынести логику XP, стриков и достижений в отдельные доменные сервисы (`XpService`, `StreakService`, `AchievementService`), оставив в нотификаторе только координацию процесса.

### 3.3 Унификация UI
Создать универсальный `GoalSetupScreen`, который принимает параметры (номер шага, заголовок, провайдер данных), вместо дублирования файлов.

### 3.4 Улучшение AI-слоя
Внедрить валидацию схем для ответов AI и оптимизировать промпты для получения более стабильного JSON.

### 3.5 Тестирование
На текущий момент в проекте отсутствуют unit-тесты для бизнес-логики (XP, начисление штрафов, расчет стриков). Покрытие этих зон тестами является приоритетом перед внедрением сетевого слоя.
