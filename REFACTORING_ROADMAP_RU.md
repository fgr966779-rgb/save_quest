# Дорожная карта рефакторинга PiggyVault (Фаза 2)

Этот документ описывает приоритетные шаги по устранению технического долга и подготовке архитектуры к масштабированию.

## Этап 1: Рефакторинг N-Goals (Критический приоритет)

**Цель:** Уйти от хардкода двух целей и позволить пользователю создавать любое количество целей.

1.  **Модификация схемы БД (`database.dart`):**
    *   Создать таблицу `DepositAllocations (id, deposit_id, goal_id, amount_cents)`.
    *   Добавить миграцию (v9) для переноса данных из `Deposits.goalAAmount` и `Deposits.goalBAmount` в новую таблицу.
    *   Удалить устаревшие поля из таблицы `Deposits`.
2.  **Обновление бизнес-логики (`SavingsNotifier`):**
    *   Изменить метод `createDeposit`, чтобы он принимал `Map<String, double> allocations` (ID цели -> процент/сумма).
    *   Реализовать итерацию по аллокациям при сохранении в БД.
3.  **Рефакторинг UI:**
    *   Заменить `DualProgressRing` на `MultiGoalProgress` (поддерживающий список целей).
    *   Заменить `SplitSlider` на систему динамических слайдеров или полей ввода для N целей.
    *   Объединить `GoalASetupScreen` и `GoalBSetupScreen` в один универсальный `GoalFormScreen`.

## Этап 2: Декомпозиция God Object (Высокий приоритет)

**Цель:** Разделить `SavingsNotifier` на модульные сервисы.

1.  **Создание Domain Services:**
    *   `GamificationService`: расчет XP, уровней и логика лутбоксов.
    *   `StreakService`: (уже частично есть, расширить) логика серий.
    *   `AchievementService`: (расширить) проверка условий наград.
2.  **Рефакторинг провайдера:**
    *   `SavingsNotifier` должен вызывать методы этих сервисов внутри транзакции БД, отвечая только за координацию процесса "Внесок -> Обновление балансов -> Обновление профиля".

## Этап 3: Повышение надежности ИИ и данных

1.  **Интеграция с OpenRouter:**
    *   Внедрить строгую валидацию JSON через JSON Schema (или аналоги на Dart).
    *   Улучшить промпты, требуя четкого следования формату.
    *   Вынести системные промпты в отдельные файлы ресурсов.
2.  **Улучшение BackupService:**
    *   Автоматизировать сериализацию моделей Drift (использовать встроенные методы `toJson`).
    *   Улучшить синхронизацию Hive-настроек, сделав их частью общей структуры бэкапа более формально.

## Этап 4: Тестирование и Стабильность

1.  **Unit-тесты:**

2.  **L10n:**
