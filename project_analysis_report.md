# Отчёт по глубокому анализу проекта PiggyVault (Обновление: Июнь 2026)

## 1. Обзор архитектуры
Проект успешно прошел этап MVP (Фаза 1). Архитектура базируется на:
*   **State Management:** Riverpod. Наблюдается тенденция к усложнению логики внутри `SavingsNotifier` (God Object), что требует декомпозиции.
*   **Database:** Drift (SQLite) для реляционных данных и Hive для настроек и локальных хранилищ.
*   **AI:** Интеграция с OpenRouter (DeepSeek) через `OpenRouterService`.

## 2. Анализ критических проблем и технического долга

### 2.1 Масштабируемость целей (Критично 🚨)
*   **Проблема:** В `database.dart`, `SavingsNotifier`, `DashboardScreen` и `DepositScreen` логика жестко завязана на ID `goal_a` и `goal_b`.
*   **Последствия:** Невозможно добавить 3-ю цель или использовать приложение с одной целью без ошибок или пустот в UI.
*   **Технический долг:** Колонки `goalAAmount` и `goalBAmount` в таблице `Deposits` должны быть вынесены в отдельную таблицу аллокаций.

### 2.2 Декомпозиция логики (God Object)
*   **Проблема:** Метод `SavingsNotifier.createDeposit` разросся до ~300 строк. Он управляет транзакциями, XP, уровнями, стриками, лутбоксами и ачивками.
*   **Риск:** Высокая сложность поддержки и риск регрессий при любых изменениях в системе геймификации.

### 2.3 Дублирование кода (Onboarding)
*   **Проблема:** Экраны `goal_a_setup_screen.dart` и `goal_b_setup_screen.dart` практически идентичны.
*   **Рекомендация:** Объединить их в один параметризуемый экран `GoalSetupScreen`.

### 2.4 Фрагментация данных геймификации
*   **Проблема:** Данные о прогрессе игрока хранятся в разных местах: `UnlockedAchievements` (Drift), `Badges` (JSON в `UserProfile`), `Milestones` (Hive).
*   **Риск:** Отсутствие атомарности при обновлении наград.

### 2.5 Качество AI-интеграции
*   **Проблема:** Парсинг ответов AI (Bounty, Insights) использует регулярные выражения, что делает систему хрупкой.
*   **Рекомендация:** Перейти на структурированный вывод (JsonSchema) и типизированные модели данных.

## 3. Рекомендации по рефакторингу для Фазы 2

1.  **N-Goals Refactoring:**
    *   Создать таблицу `DepositAllocations(id, deposit_id, goal_id, amount)`.
    *   Удалить специфичные для целей поля из таблицы `Deposits`.
    *   Обновить `DualProgressRing` для поддержки динамического количества сегментов.
2.  **Domain Services:**
    *   Вынести расчеты в `XpService`, `StreakService`, `RewardService`. `SavingsNotifier` должен только координировать вызовы этих сервисов внутри транзакции.
3.  **Sync Readiness:**
    *   Добавить `updated_at` во все таблицы Drift.
    *   Перейти на UUID для первичного ключа в `UserProfiles` (сейчас используется статический `1`).
4.  **Testing:**
    *   Покрыть Unit-тестами расчеты в `MoneyUtils`, `XpService` и `StreakService`.
