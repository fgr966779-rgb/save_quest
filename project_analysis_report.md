# Подробный технический аудит проекта PiggyVault (Июль 2026)

## 1. Резюме
Проект PiggyVault представляет собой мощную платформу для геймифицированных накоплений с глубокой проработкой визуального стиля (Cyberpunk). Однако текущее состояние кодовой базы характеризуется значительным техническим долгом, накопленным на этапе MVP, что препятствует внедрению облачной синхронизации и расширению количества целей.

## 2. Глубокий анализ технического долга

### 🚨 2.1 Хардкодинг целей (N-Goals Problem)
Это наиболее критическая архитектурная проблема. Логика приложения жестко завязана на две цели (`goal_a` и `goal_b`).
*   **База данных:** Таблица `Deposits` содержит явные колонки `goalAAmount` и `goalBAmount`.
*   **Бизнес-логика:** В `AppDatabase` методы `saveDepositAndUpdateGoals` и `softDeleteDepositAndUpdateGoals` принимают параметры для двух конкретных целей.
*   **UI-компоненты:** Виджеты `DualProgressRing` и `SplitSlider` жестко запрограммированы на работу только с двумя значениями прогресса.
*   **Последствия:** Добавление третьей цели невозможно без переписывания значительной части ядра приложения.

### 🧩 2.2 SavingsNotifier как God Object
Класс `SavingsNotifier` (lib/core/providers/savings_notifier.dart) перегружен ответственностью.
*   **Проблема:** Метод `createDeposit` представляет собой процедурный блок длиной более 170 строк, который одновременно управляет транзакциями БД, расчетом XP, логикой стриков, проверкой достижений, дропом лутбоксов и обновлением квестов.
*   **Сложность:** Логика "критических ударов" и множителей XP перемешана с кодом сохранения данных.
*   **Риски:** Любое изменение в механике геймификации может случайно сломать процесс сохранения денег.

### 👯 2.3 Дублирование кода в Onboarding
Экраны настройки целей (`goal_a_setup_screen.dart` и `goal_b_setup_screen.dart`) идентичны на **88%**.
*   **Детали:** Из 304 строк кода в каждом файле, 269 строк полностью совпадают.
*   **Рекомендация:** Объединить в единый `GoalSetupScreen` с параметром индекса цели.

### 🌍 2.4 Локализация и AI-интеграция
*   **Локализация:** Файл `l10n.dart` содержит гигантский жестко закодированный Map. Это не соответствует стандартам Flutter (ARB файлы) и затрудняет поддержку.
*   **Хрупкий парсинг AI:** `BountyProvider` использует простые методы работы со строками для извлечения JSON из ответов OpenRouter. Это часто приводит к ошибкам, если нейросеть добавляет лишний текст.

## 3. Состояние качества кода

### 3.1 Статический анализ
На данный момент `flutter analyze` выдает 11 предупреждений:
*   `use_build_context_synchronously` в `dashboard_screen.dart` и `settings_screen.dart`.
*   `unused_local_variable` (например, `brightness`) в нескольких экранах.
*   `unused_element` в `pets_screen.dart`.

### 3.2 Тестирование
Покрытие тестами критически низкое. В проекте активен только один тест (`widget_test.dart`), который проверяет лишь компиляцию ProviderScope. Юнит-тесты для сложной логики XP, стриков и достижений полностью отсутствуют.

1.  **Миграция БД на версию 9:**

    *   Рефакторинг `SplitSlider` и `DualProgressRing` для поддержки динамического списка целей.
    *   Унификация экранов онбординга.
