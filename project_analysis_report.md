# Глубокий технический анализ проекта PiggyVault

## 1. Архитектурный обзор
Проект PiggyVault представляет собой сложное мобильное приложение на Flutter с элементами RPG и геймификации. Используется современный стек: **Riverpod 2** для управления состоянием, **Drift (SQLite)** для реляционных данных и **Hive** для легковесных настроек.

## 2. Ключевые архитектурные проблемы

### 2.1 Проблема "Божественного метода" (God Method)
Класс `SavingsNotifier` и его метод `createDeposit` в `lib/core/providers/savings_notifier.dart` перегружены ответственностью. Один метод выполняет:
*   Валидацию и конвертацию валют.
*   Открытие БД-транзакции.
*   Расчет XP с учетом множителей стріков, классов и навыков.
*   Логику критических ударов.
*   Начисление кредитов.
*   Обновление бейджей (Badges) через JSON.
*   Обновление Альянсов (Squads).
*   Валидацию достижений (Achievements).
*   Генерацию лутбоксов.
*   Проверку AI-баунти и ежедневных квестов.

**Риск:** Крайне высокая сложность поддержки и тестирования. Любое изменение в логике XP может сломать начисление кредитов или детекцию достижений.

### 2.2 Несогласованность хранилищ данных (Data Split)
Данные приложения разделены между **Drift (SQL)** и **Hive (NoSQL)** без четкой границы:
*   **Drift:** Профиль пользователя, Навыки, Цели, Питомцы.
*   **Hive:** Ежедневные квесты (`daily_quests`), AI Баунти (`active_bounty`), Настройки приватности.

**Проблема:** Невозможно обеспечить атомарность транзакций. Если запись депозита в Drift прошла успешно, а обновление квеста в Hive (через `SettingsService`) завершилось сбоем, состояние приложения станет неконсистентным.

### 2.3 Дублирование систем наград
В проекте сосуществуют две параллельные системы:
1.  **Achievements (Достижения):** Описаны в `achievement_model.dart`, хранятся в отдельной таблице БД `UnlockedAchievements`.
2.  **Badges (Бейджи):** Описаны в `badge_model.dart`, хранятся как JSON-строка внутри `UserProfile.avatarConfig`.

Многие проверки дублируются (например, проверка стріков на 7/14/30 дней есть и там, и там). Это создает путаницу для пользователя и усложняет код.

## 3. Технический долг и качество кода

### 3.1 Состояние Линтера
На данный момент `flutter analyze` сообщает о **342 проблемах**.
*   Большинство — использование устаревшего `withOpacity` (нужно заменить на `withValues` для Flutter 3.27+).
*   Множество предупреждений о `use_super_parameters`.
*   Неиспользуемые импорты и поля в экранах настроек и дашборда.

### 3.2 Локализация
Локализация реализована через кастомный `l10n.dart` и JSON-карты. Хотя это работает, проект не использует стандартные `.arb` файлы и генерацию кода `AppLocalizations`, что затрудняет поддержку профессиональных переводов и плюрализации.

### 3.3 Тестирование
В проекте практически отсутствуют Unit и Widget тесты (кроме дефолтного `widget_test.dart`). Учитывая сложность формул XP и стріков, это критический недостаток.

## 4. Состояние фич (Анализ по Roadmap)

*   **Squads (Альянсы):** Реализован только UI и локальные заглушки. Требуется серверная часть для реального взаимодействия.
*   **Skill Tree:** Реализовано хорошо, но требует балансировки стоимости навыков.
*   **Terminal (CLI):** Интересная фича, но пока мало команд. Интеграция Hacker XP через терминал — сильная сторона.
*   **AI Coach:** Интеграция с OpenRouter выполнена корректно, но завязана на API-ключ пользователя.

## 5. Рекомендации по исправлению

1.  **Рефакторинг `SavingsNotifier`:** Вынести логику расчета наград в отдельные сервисы (`XpCalculator`, `AchievementValidator`, `QuestManager`).
2.  **Миграция данных:** Перенести квесты и баунти из Hive в Drift для обеспечения целостности данных.
3.  **Унификация наград:** Объединить Achievements и Badges в единую систему с общей таблицей в БД.
4.  **Очистка кода:** Исправить автоматизированными средствами (`dart fix --apply`) массовые предупреждения линтера.
5.  **Тесты:** Написать тесты для `SavingsNotifier` и `CoreSkillSystem`, так как это ядро приложения.
