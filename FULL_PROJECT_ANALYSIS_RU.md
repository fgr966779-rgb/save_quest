# Полный технический анализ проекта PiggyVault (Июнь 2026)

## 1. Архитектура и стек
*   **Фреймворк:** Flutter 3.6.2 (Dart 3).
*   **State Management:** Riverpod 2.6.
*   **База данных:** Drift (SQLite) для структурированных данных, Hive для настроек и простых коллекций.
*   **Архитектурный паттерн:** Feature-driven (модули `dashboard`, `deposit`, `gamification`, `onboarding`, `remote_control`).

## 2. Глубокий анализ проблем

### 🚨 2.1 Масштабируемость целей (N-Goals) — КРИТИЧНО
*   **Проблема:** Таблица `Deposits` содержит хардкод колонок `goalAAmount` и `goalBAmount`.
*   **Последствия:** Невозможно добавить 3-ю цель без изменения схемы БД и сотен строк кода.
*   **Затронуто:** `SavingsNotifier`, `AchievementService`, `FinancialHealthProvider`, `SplitSlider`, `DualProgressRing`.

### 🏗️ 2.2 God Object: `SavingsNotifier`
*   **Проблема:** Один класс координирует транзакции БД, расчет XP, обновление стриков, ачивки, баунти и квесты.
*   **Техдолг:** Логика достижений встроена прямо в метод `createDeposit`. Это делает транзакции тяжелыми и хрупкими.

### 🤖 2.3 Хрупкость AI-интеграции
*   **Проблема:** `PriceAnalysisService` и `BountyProvider` используют `indexOf('{')` и регулярные выражения для извлечения JSON.
*   **Риск:** Любое изменение в стиле ответа AI (DeepSeek) приведет к ошибкам парсинга. Требуется переход на структурированный вывод или валидацию схем.

### 👯 2.4 Дублирование и Консистентность UI
*   **Onboarding:** Экраны `goal_a_setup_screen.dart` и `goal_b_setup_screen.dart` на 90% идентичны.
*   **Дизайн-система:** Смешение старых "неоновых" элементов и новой минималистичной системы `AppColors`.

### 📡 2.5 Remote Control (Удаленное управление)
*   **Реализация:** Кастомный протокол поверх WebSockets с SHA-256 HMAC аутентификацией.
*   **Заметки:** Есть отличный fallback на PowerShell для управления без `robotjs`.
*   **Проблема:** Передача кадров идет через сырой WS без шифрования (кроме хендшейка). Потенциальные проблемы с производительностью при высоком разрешении.

### ⚙️ 2.6 Атомарность и Состояние (Weekly Challenges)
*   **Проблема:** Обновление `WeeklyChallengeService` происходит вне транзакции `SavingsNotifier`. При ошибке в одной из систем данные могут рассинхронизироваться.

## 3. Резюме технического долга

| Компонент | Риск | Проблема |
| :--- | :--- | :--- |
| **Data Schema** | High | Жесткая структура целей (v8), отсутствие UUID. |
| **Logic** | Medium | Избыточная ответственность `SavingsNotifier`. |
| **Testing** | High | Почти полное отсутствие тестов (только один проверочный тест). |
| **L10n** | Low | Map-базированная локализация вместо `.arb`. |

## 4. Рекомендации (Roadmap)

1.  **Phase 2 Step 1:** Миграция БД на v9 (UUID + `DepositAllocations`).
2.  **Phase 2 Step 2:** Унификация Onboarding в один динамический экран.
3.  **Phase 2 Step 3:** Рефакторинг `SavingsNotifier` (вынос логики наград в слушатели).
4.  **Security:** Внедрение безопасного транспорта для Remote Control.
