# Полный аналитический отчет по проекту PiggyVault (Июль 2026)

## 1. Технический стек и архитектура

### Основные технологии:
*   **Фреймворк:** Flutter (Material 3).
*   **Управление состоянием:** Riverpod (StateNotifier, AsyncValue).
*   **База данных (Реляционная):** Drift (SQLite). Хранит цели, депозиты, профиль пользователя.
*   **База данных (Key-Value):** Hive. Хранит настройки, еженедельные челенджи, квесты и временные игровые данные.
*   **Навигация:** GoRouter.
*   **Интеграция с ИИ:** OpenRouter (DeepSeek) для генерации советов, баунти-миссий и анализа цен.

### Структура проекта:
*   `lib/core`: Общие сервисы (gamification, notification), виджеты, провайдеры и константы.
*   `lib/data`: Слой данных (Drift database, Hive settings, Backup service).
*   `lib/features`: Функциональные модули (dashboard, deposit, gamification, onboarding, settings).
*   `remote_server`: Node.js сервер для функционала удаленного управления ПК.

## 2. Выявленные архитектурные проблемы и технический долг

### 2.1 Проблема "Hardcoded N-Goals" (Критично 🚨)
Вся система жестко привязана к существованию ровно двух целей (`goal_a` и `goal_b`).
*   **Database:** Таблица `Deposits` содержит колонки `goalAAmount` и `goalBAmount`.
*   **Logic:** `SavingsNotifier.createDeposit` принимает фиксированные параметры для двух целей.
*   **Services:** `AchievementService` и `MilestoneService` содержат проверки `if (goalId == 'goal_a')`.
*   **UI:** Виджеты `SplitSlider` и `DualProgressRing` рассчитаны только на две цели.
*   **Последствия:** Невозможность добавить 3-ю цель без переписывания значительной части кода.

### 2.2 SavingsNotifier как "God Object" (Высокая важность ⚠️)
Класс `SavingsNotifier` выполняет слишком много задач:
*   Управление транзакциями БД.
*   Расчет XP и уровней.
*   Логика стрик-системы (серий).
*   Проверка достижений.
*   Управление лутбоксами.
*   Интеграция с квестами и баунти.
*   **Последствия:** Трудности при тестировании и высокий риск внесения багов при модификации любой игровой механики.

### 2.3 Хрупкий парсинг ответов ИИ (Средняя важность ⚠️)
В `OpenRouterService`, `PriceAnalysisService` и `BountyProvider` используется ручной парсинг JSON с помощью регулярных выражений и `replaceAll`.
*   **Риски:** Если модель ИИ изменит формат ответа (например, добавит пояснительный текст вне JSON), парсинг упадет. Отсутствует валидация схем ответов.

### 2.4 Консистентность данных (Средняя важность ⚠️)
Обновления в `WeeklyChallengeService` и `DailyQuest` происходят вне основной транзакции базы данных в `SavingsNotifier`.
*   **Риски:** Если запись депозита в БД пройдет успешно, а приложение упадет до обновления челенджей в Hive, данные рассинхронизируются.

## 3. Дублирование кода и возможности унификации

### 3.1 Экраны онбординга
Файлы `goal_a_setup_screen.dart` и `goal_b_setup_screen.dart` практически идентичны (90% общего кода).
*   **Рекомендация:** Объединить в один универсальный `GoalSetupScreen(int index)`.

### 3.2 Виджеты прогресса
Виджеты на главном экране и в деталях целей часто дублируют логику отрисовки прогресс-баров и карточек.
*   **Рекомендация:** Унифицировать `GoalCard` для использования в списках и деталях.

## 4. Рекомендации для Фазы 2

### 4.1 Рефакторинг на N-целей (Приоритет №1)
1.  **Схема БД:** Создать таблицу `DepositAllocations (deposit_id, goal_id, amount_cents)`.
2.  **Миграция:** Перенести данные из колонок `goalAAmount/goalBAmount` в новую таблицу.
3.  **UI:** Перевести `SplitSlider` на работу со списком `List<GoalAllocation>`.

### 4.2 Декомпозиция SavingsNotifier
Вынести игровую логику в специализированные доменные сервисы:
*   `LevelingService` (XP, уровни).
*   `RewardService` (Лутбоксы, ачивки).
*   `DepositCoordinator` (только управление атомарной транзакцией).

### 4.3 Подготовка к Cloud Sync
1.  **UUID:** Убедиться, что ВСЕ таблицы используют UUID (сейчас `UserProfiles` использует `id: 1`).
2.  **Таймстампы:** Добавить колонку `updatedAt` и флаг `isSynced` для всех сущностей.

### 4.4 Стабилизация ИИ
Внедрить более надежный метод извлечения JSON или использовать Structured Output (если поддерживает провайдер). Добавить блоки try-catch с более детальной обработкой ошибок.
