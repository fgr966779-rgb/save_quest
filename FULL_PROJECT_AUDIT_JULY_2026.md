# Полный технический аудит проекта PiggyVault (Июль 2026)

## 1. Обзор архитектуры
Проект представляет собой Flutter-приложение с глубокой геймификацией.
*   **Управление состоянием:** Riverpod (StateNotifier + AsyncValue). Структура провайдеров логична, но некоторые из них перегружены.
*   **База данных:** Drift (SQLite) для структурированных данных и Hive для настроек. Схема данных (версия 8) стабильна, но имеет архитектурные тупики.
*   **Навигация:** GoRouter (декларативный подход).
*   **AI-интеграция:** OpenRouter (DeepSeek) для генерации контента и анализа.
*   **Стиль:** Киберпанк-дизайн с кастомными отрисовками (`CustomPainter`).

## 2. Обнаруженные проблемы и Технический долг

### 2.1 Проблема "N-Целей" (Критично) 🚨
Это самый большой архитектурный долг. Весь проект (от БД до UI) завязан на существование ровно двух целей: "Goal A" и "Goal B".
*   **БД:** Таблица `Deposits` содержит колонки `goal_a_amount` и `goal_b_amount`. Добавление 3-й цели потребует миграции и изменения всех SQL-запросов.
*   **Логика:** `SavingsNotifier` и `AchievementService` жестко прописывают ID `goal_a`/`goal_b`.
*   **UI:** Виджеты `DualProgressRing` и `SplitSlider` не поддерживают больше двух элементов.

### 2.2 Дублирование кода (UI) ⚠️
*   **Onboarding:** Экраны `goal_a_setup_screen.dart` и `goal_b_setup_screen.dart` идентичны на ~95%. Это затрудняет поддержку и изменение логики настройки целей.
*   **Решение:** Создать единый `GoalSetupScreen` с параметрами.

### 2.3 "Божественный объект" (God Object) 🧠
`SavingsNotifier` выполняет слишком много задач одновременно:
1.  Управление транзакциями БД.
2.  Расчет XP и уровней.
3.  Логика стриктов и токенов заморозки.
4.  Проверка достижений и квестов.
5.  Взаимодействие с AI-баунти.
*   **Риск:** Высокая сложность тестирования и риск регрессий при любых изменениях.

### 2.4 Готовность к Cloud Sync (Масштабируемость) ☁️
*   **ID:** Профиль пользователя (`UserProfiles`) использует захардкоженный ID `1`. Для синхронизации между устройствами необходим переход на UUID.
*   **Метаданные:** В таблицах отсутствуют колонки `updated_at` и `is_synced`, что делает невозможным реализацию стратегии "Last Write Wins" для оффлайн-работы.

### 2.5 Хрупкость AI-парсинга 🤖
*   Логика в `BountyProvider` и `PriceAnalysisService` полагается на очистку JSON-строк через `replaceAll`. Если AI вернет текст вне формата или с неожиданными комментариями, приложение может упасть или использовать fallback.

### 2.6 Локализация 🌐
*   `l10n.dart` представляет собой гигантскую Map-структуру. Это "бутылочное горлышко" для добавления новых языков и поддержки перевода внешними сервисами.

## 3. Анализ Remote Server (Дистанционное управление)
*   Реализован на Node.js + WebSocket.
*   Использует SHA-256 challenge-response для безопасности.
*   **Производительность:** Целевой FPS ~22. Этого достаточно для управления, но может быть недостаточно для динамичного контента.
*   **Безопасность:** Пароль захардкожен (`cybervault`), что допустимо для локального использования, но требует изменения при выходе в сеть.

## 4. Состояние тестирования 🧪
*   Тестовое покрытие критически низкое. Отсутствуют Unit-тесты для ключевой бизнес-логики (XP, Streaks, Achievements). Есть только базовый `widget_test.dart`.

3.  **Декомпозиция Notifier:** Вынести логику геймификации в отдельные доменные сервисы.
