# Глубокий аудит проекта PiggyVault (Июль 2026)

## 1. Резюме проекта
**PiggyVault** — это высокотехнологичное Flutter-приложение для управления финансами с глубокой интеграцией игровых механик (RPG-составляющая) и искусственного интеллекта. Проект находится на стадии завершения Фазы 1 (MVP) и готовится к Фазе 2 (Социальные функции и Облачная синхронизация).

---

## 2. Архитектурный анализ

### 2.1 Технологический стек
*   **Фреймворк:** Flutter (SDK ^3.6.2).
*   **Управление состоянием:** Riverpod (используются генераторы, StateNotifier).
*   **База данных:** Drift (SQLite) для структурированных данных, Hive для настроек и простых ключ-значение.
*   **Навигация:** GoRouter.
*   **AI:** OpenRouter (DeepSeek) для генерации баунти и анализа цен.

### 2.2 Структура папок
*   `lib/core`: Ядро приложения (темы, константы, навигация, общие провайдеры и сервисы).
*   `lib/data`: Слой данных (Drift БД, Backup-сервис, Settings-сервис).
*   `lib/features`: Модульная структура по фичам (gamification, dashboard, deposit, onboarding и др.).
*   `remote_server`: Отдельный Node.js сервер для функции дистанционного управления ПК.

## 3. Выявленные проблемы и технический долг (Critical)

### 3.1 Хардкод целей (N-Goals Problem)
*   **Локация:** `lib/data/database.dart`, `lib/core/providers/savings_notifier.dart`, `lib/core/widgets/split_slider.dart`, `lib/features/onboarding/`.
*   **Суть:** Логика приложения жестко завязана на две цели: `goal_a` и `goal_b`. Таблица `Deposits` имеет колонки `goalAAmount` и `goalBAmount`.
*   **Риск:** Невозможность создания 3-й и более целей без переписывания ядра БД и UI.

### 3.2 God Object: SavingsNotifier
*   **Локация:** `lib/core/providers/savings_notifier.dart`.
*   **Суть:** Один класс отвечает за:
    1. Создание депозитов в БД.
    2. Расчет XP и уровней.
    3. Обработку стрик-механики.
    4. Выпадение лутбоксов.
    5. Проверку ачивок.
    6. Координацию с баунти и квестами.
*   **Риск:** Огромная сложность тестирования и поддержки. Любое изменение в механике XP может сломать логику депозита.

### 3.3 Хрупкий парсинг AI-ответов
*   **Локация:** `lib/core/services/price_analysis_service.dart`, `lib/features/gamification/providers/bounty_provider.dart`.
*   **Суть:** Использование `indexOf('{')` и `substring` для извлечения JSON из текста. Если AI добавит лишнюю скобку или изменит формат, парсинг упадет.
*   **Рекомендация:** Использовать структурированный вывод (JsonSchema) или более надежные библиотеки для валидации схем.

### 3.4 Дублирование UI кода
*   **Локация:** `lib/features/onboarding/screens/goal_a_setup_screen.dart` и `goal_b_setup_screen.dart`.
*   **Суть:** Экраны идентичны на 95%. Различаются только названиями переменных и цветами.
*   **Рекомендация:** Объединить в один `GoalSetupScreen(goalType: 'A' | 'B')` или передавать конфигурацию через параметры.

### 3.5 Проблемы синхронизации (Sync Readiness)
*   **Локация:** `AppDatabase`.
*   **Суть:** Отсутствуют поля `updated_at` и `is_synced` во многих таблицах. Используются жесткие ID (например, `id: 1` для профиля).
*   **Риск:** Невозможно реализовать корректное слияние данных (Conflict Resolution) при подключении облака.

## 4. Глубокий анализ фич

### 4.1 Гамификация
Система очень богатая (Skill Tree, Avatar Builder, Pets, Lootboxes, Classes). Однако многие механики (например, `AchievementService`) содержат хардкод проверки конкретных целей (например, `halfway_ps5` проверяет только `goal_a`).

### 4.2 Дистанционное управление (Remote Control)
Уникальная фича, реализованная через WebSocket и Node.js сервер.
*   **Плюс:** Технически сложное и интересное решение.
*   **Минус:** Безопасность (пароль передается в открытом виде или через простой хеш). Требует отдельного аудита безопасности.

### 4.3 Локализация (L10n)
Реализована через самописный `AppLocalizations` с огромным `Map` внутри Dart-файла.
*   **Проблема:** Это замедляет компиляцию и усложняет работу переводчикам.
*   **Рекомендация:** Перейти на стандартные `.arb` файлы и пакет `flutter_localizations`.

## 5. Рекомендации к действию

1.  **Рефакторинг БД:** Миграция на схему с таблицей `DepositAllocations` для поддержки любого количества целей.
2.  **Декомпозиция Notifier:** Вынос XP, Achievements и Streaks в отдельные доменные сервисы.
3.  **Унификация Onboarding:** Удаление дублирующих экранов настройки целей.
4.  **UUID везде:** Замена всех оставшихся целочисленных или хардкодных ID на UUID для подготовки к Sync.
5.  **Robust AI Parsing:** Внедрение защищенного парсера JSON с обработкой ошибок.
