# Глубокий аудит и технический анализ проекта PiggyVault (Июль 2026)

## 1. Общее состояние архитектуры

Проект PiggyVault успешно прошел фазу MVP (Фаза 1) и имеет прочный фундамент для дальнейшего развития. Однако архитектура содержит ряд ограничений, которые станут критическими при переходе к Фазе 2 (Social & Cloud).

### Стек технологий:
*   **UI Framework:** Flutter 3.6.2 (Stable).
*   **State Management:** Riverpod 2.5.1. Используется паттерн `StateNotifier` и генераторы.
*   **Persistence:**
    *   **Drift (SQLite):** Для структурированных данных (транзакции, цели, профили).
    *   **Hive:** Для настроек (SettingsService), милстоунов и локальных уведомлений.
*   **Navigation:** GoRouter 14.2.0.
*   **AI Integration:** OpenRouter (DeepSeek V3/V4).

## 2. Инвентаризация технического долга

### 2.1 Критическая зависимость от 2-х целей (N-Goals Debt) 🚨
Самая большая архитектурная проблема — жесткое кодирование двух целей (`goal_a`, `goal_b`) на всех уровнях:
*   **Database Schema:** Таблица `Deposits` имеет колонки `goalAAmount` и `goalBAmount`. Это делает невозможным создание 3-й цели без изменения схемы.
*   **Logic:** `SavingsNotifier.createDeposit` принимает `goalAPercent` и жестко рассчитывает остаток для `goal_b`.
*   **UI Widgets:** `SplitSlider` и `DualProgressRing` рассчитаны исключительно на две цели.
*   **Services:** `AchievementService` и `MilestoneService` используют жестко заданные ID для проверки прогресса.

### 2.2 SavingsNotifier как "God Object" ⚠️
Хотя часть логики (XP, Streaks) была вынесена в отдельные сервисы, `SavingsNotifier` остается центральным координатором, который управляет:
*   Транзакциями БД.
*   Валидацией ачивментов.
*   Обновлением профиля.
*   Запуском баунти и квестов.
*   Обновлением сквадов.
Это усложняет тестирование и поддержку.

### 2.3 Дублирование UI и логики 📋
*   **Onboarding:** Экраны `GoalASetupScreen` и `GoalBSetupScreen` идентичны на ~95%. Их нужно унифицировать в один `GoalSetupScreen(index)`.
*   **L10n:** Локализация через `Map` в `l10n.dart` неудобна для крупных проектов. Рекомендуется переход на стандартные `.arb` файлы.

### 2.4 Хрупкость AI-парсинга 🤖
*   `PriceAnalysisService` использует `_extractJson` через `indexOf`/`lastIndexOf` и `_toKopecks` через RegExp. Любое непредсказуемое изменение в ответе ИИ может привести к ошибкам.

### 2.5 Готовность к синхронизации (Sync Readiness) ☁️
*   Версия схемы БД — 8. Отсутствуют поля `updatedAt` и `isSynced`, которые необходимы для Cloud Sync.
*   Использование автоинкрементного ID `1` для `UserProfiles` помешает работе с несколькими устройствами.

## 3. Анализ игровых механик и Gamification

Проект имеет очень глубокую систему геймификации:
*   **Классы персонажей:** Warrior, Mage, Rogue с уникальными бонусами.
*   **Skill Tree:** 3 ветки (Hacker, Magnate, Resilience), влияющие на геймплей.
*   **Avatar Builder:** Кастомизация робота за Кибер-Кредиты.
*   **Экономика:** XP, Кристаллы, Кибер-Кредиты, SP (Skill Points).
*   **Bounties & Quests:** Система ежедневных заданий, интегрированная с ИИ.

**Проблема:** Логика ачивментов в `AchievementService` использует строковые константы (`halfway_ps5`), что усложняет добавление нового контента без изменения кода.

## 4. Приоритетный Roadmap для Фазы 2

### Шаг 1: Рефакторинг N-Goals (Наивысший приоритет)
1.  **Миграция БД (Версия 9):**
    *   Создать таблицу `DepositAllocations(depositId, goalId, amount)`.
    *   Удалить жесткие колонки из `Deposits`.
    *   Добавить `updatedAt` и `isSynced` во все таблицы.
2.  **Генерализация виджетов:** Превратить `DualProgressRing` в `MultiProgressRing`, принимающий список целей.
3.  **Обновление SavingsNotifier:** Переход на `Map<String, double> allocations`.

### Шаг 2: Декомпозиция и Чистая Архитектура
1.  Вынести координацию транзакций из `SavingsNotifier` в `CreateDepositUseCase`.
2.  Создать `GoalService` для управления жизненным циклом целей (CRUD, прогресс).

### Шаг 3: Cloud Sync & Social
1.  Интеграция `SyncService` (Supabase или Firebase).
2.  Оживление `Squads` через Real-time DB.
3.  Переход на UUID для всех сущностей.

### Шаг 4: UI Unification
1.  Создание универсального `GoalSetupScreen`.
2.  Рефакторинг L10n на ARB.

## 5. Вывод

Проект имеет высокий потенциал благодаря уникальному сочетанию финансового инструмента и глубокого киберпанк-сеттинга. Технический долг в виде жестко закодированных целей является основным препятствием для масштабирования, и его решение должно быть первым шагом в Фазе 2.
