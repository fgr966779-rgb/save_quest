# Полный технический анализ проекта PiggyVault (Июль 2026)

## 1. Введение
Проект **PiggyVault** — это геймифицированное мобильное приложение для управления личными финансами, построенное на Flutter. Текущее состояние проекта характеризуется как "стабильный MVP с накопленным архитектурным долгом", готовый к переходу на Фазу 2 (Облачная синхронизация и социальные функции).

---

## 2. Архитектурный обзор

### 2.1 Стек технологий
*   **UI Framework:** Flutter (Material 3).
*   **State Management:** Riverpod. Используется активно, но наблюдается перегрузка некоторых провайдеров.
*   **Persistence:**
    *   **Drift (SQLite):** Для структурированных данных (транзакции, цели, профиль). Текущая версия схемы: 8.
    *   **Hive:** Для легковесных настроек, состояния онбординга и "celebrated" милстоунов.
*   **Navigation:** GoRouter. Реализована чистая навигация с поддержкой ShellRoute для док-бара.
*   **AI Integration:** OpenRouter (DeepSeek) для анализа цен и финансового коучинга.

### 2.2 Структура папок
Проект следует Feature-First подходу:
*   `lib/core`: Общие компоненты, темы, константы, сервисы и базовые модели.
*   `lib/data`: Слой данных (Drift, Hive, сервисы бэкапа).
*   `lib/features`: Функциональные модули (gamification, dashboard, deposit, onboarding, settings).

## 3. Глубокий анализ проблем и технического долга

### 3.1 Проблема "Hardcoded N-Goals" (Критическая)
Это самое значительное ограничение системы.
*   **Суть:** Таблица `Deposits` содержит колонки `goalAAmount` и `goalBAmount`. Весь UI (слайдеры, кольца прогресса) и бизнес-логика (`SavingsNotifier`, `AppDatabase`) жестко завязаны на две цели: "Goal A" и "Goal B".
*   **Последствия:** Невозможность создания 3-й и последующих целей без изменения схемы БД и переписывания десятков файлов.
*   **Местонахождение:** `lib/data/database.dart`, `lib/core/providers/savings_notifier.dart`, `lib/core/widgets/split_slider.dart`, `lib/core/widgets/dual_progress_ring.dart`.

### 3.2 SavingsNotifier как "God Object"
`SavingsNotifier` (в `lib/core/providers/savings_notifier.dart`) выполняет слишком много задач:
1.  Создание транзакций в БД.
2.  Расчет XP (базовый, бонусный, специфический).
3.  Логика стрик-системы (хотя часть вынесена в `StreakService`).
4.  Валидация достижений.
5.  Логика выпадения лутбоксов.
6.  Обновление состояния сквадов.
*   **Рекомендация:** Декомпозировать на специализированные доменные сервисы.

### 3.3 Дублирование UI в Onboarding
Экраны `goal_a_setup_screen.dart` и `goal_b_setup_screen.dart` идентичны на 95%. Это затрудняет поддержку и изменение логики создания целей.
*   **Рекомендация:** Объединить в один универсальный `GoalSetupScreen`.

### 3.4 Хрупкость парсинга AI
`PriceAnalysisService` использует регулярные выражения и метод `_extractJson` для обработки ответов от LLM.
*   **Проблема:** При малейшем изменении формата ответа нейросети парсинг падает.
*   **Рекомендация:** Использовать Structured Output (JsonSchema) и более надежные библиотеки валидации JSON.

### 3.5 Локализация (L10n)
Реализована через гигантский `Map` в `l10n.dart`.
*   **Проблема:** Это не стандарт для Flutter. Отсутствует поддержка плюрализации, контекстных подсказок и внешних инструментов перевода.
*   **Рекомендация:** Перейти на `.arb` файлы и `flutter_gen`.

## 4. Анализ геймификации
Система геймификации глубоко проработана и является "киллер-фичей":
*   **Skill Tree:** Три ветки (Hacker, Magnate, Resilience) с реальным влиянием на геймплей.
*   **Avatar Builder:** Кастомизация аватара с системой блокировки предметов по уровню.
*   **Cyber-Events:** Поддержка временных множителей XP и кредитов.
*   **Integrity System:** Штрафы за несоблюдение финансовых советов AI.

## 5. Готовность к Фазе 2 (Cloud & Social)

### 5.1 Cloud Sync
*   **Текущий статус:** Частично готов. Большинство таблиц используют UUID.
*   **Пробелы:** Схема версии 8 не содержит полей `updatedAt` и `isSynced`. Таблица `UserProfiles` использует `id: 1`, что вызовет конфликт при мультидевайсном использовании.
*   **BackupService:** Существующий сервис бэкапа работает через JSON-файлы, что является хорошей базой для миграции в облако.

### 5.2 Social (Squads / Joint Goals)
*   **Текущий статус:** Реализован только UI и локальное хранение.
*   **Проблема:** Отсутствует сетевой слой. Все "члены сквада" сейчас — локальные записи. Требуется интеграция с Firebase/Supabase для Real-time обновлений.

## 6. Итоговые рекомендации

1.  **Рефакторинг N-Goals:** Переход на таблицу `DepositAllocations`. Это разблокирует масштабируемость.
2.  **Миграция БД на v9:** Добавление UUID для профиля и полей синхронизации.
3.  **Унификация UI:** Создание дизайн-системы виджетов, поддерживающих списки целей, а не жесткие пары.
4.  **Разделение ответственности:** Вынос логики вознаграждений из `SavingsNotifier` в `RewardCoordinator`.
5.  **Стандартизация L10n:** Переход на ARB для упрощения масштабирования на другие языки.
